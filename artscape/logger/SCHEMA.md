# Log schema (v1)

The exact format of ArtScape's run logs. The design and the reasons behind it are in `artscape/docs/logger/DESIGN.md`. If this file and the code disagree, the code is wrong. Schema version 1, from 20 Nov 2026.

## Run folder

```
runs/<run-id>/                 run id: YYYY-MM-DD_HHMM_<condition> (local time), e.g. 2026-11-20_1748_dev
  run.json                     setup of the run, written once at creation, never changed
  agents/<agent>.jsonl         one agent's events, one JSON object per line, append-only
  files/config/areas.json      copy of artscape/areas.json at run start
  files/<agent>/<seq>_<name>   long texts (prompts, answers, memory versions), never overwritten
  timeline.jsonl               all agents' events ordered by time   (generated by merge.ts)
  timeline.txt                 one readable line per event          (generated by merge.ts)
```

- If two runs start in the same minute with the same condition, the second gets a suffix: `..._dev_2`.
- `runs/` is gitignored. Back up finished runs separately.
- Only the agent files and `files/` are data. The two timeline files can be regenerated at any time with `bun artscape/logger/merge.ts <run-id>`.

## run.json

| Field | Meaning |
|---|---|
| `schema` | Schema version (1) |
| `run`, `condition` | Run id; `dev` for test runs, later `memory-on` / `memory-off` |
| `created`, `timezoneOffsetMinutes` | Creation time (ISO UTC) and the machine's offset from UTC |
| `agents` | Agents the run was created for (agents that join later with `--run` only appear in `agents/`) |
| `model`, `memory`, `note` | Language model, memory on/off, free text. `null` until those features exist |
| `versions` | `rsSdkUpstream` (pinned rs-sdk commit), `fork` (`commit`, `branch`, `dirty` of our repo at start), `bun` |
| `world` | `tickRateMs`, `xpRate`, `geEnabled`, `liveReload`, read from `server/engine/.env` at start (only these keys) |
| `configFiles` | Config files copied into the run |

## Event envelope

Every line in an agent file:

```json
{"seq":12,"t":"2026-11-20T17:49:04.512Z","tick":10233,"run":"2026-11-20_1748_dev","agent":"testbot1","type":"action","data":{...}}
```

| Field | Meaning |
|---|---|
| `seq` | Counter per agent file, 1, 2, 3, ... with no gaps. An agent that rejoins a run continues its count |
| `t` | Wall-clock time, ISO UTC with milliseconds |
| `tick` | The bot's tick count from its state, or `null` when there is no state. **Not a world clock:** the lite client counts server ticks since *that client* started, so two agents show different ticks at the same moment, and the count restarts at 0 when a client restarts. Use it for durations within one agent's session; order agents by `t` |
| `run`, `agent` | Run id and bot name (lowercase) |
| `type` | Event type, see below |
| `data` | Event fields. Values are made JSON-safe: a RegExp becomes its text (`"/^tree$/i"`), long strings are cut at 300 characters, arrays at 20 items, interaction option lists are dropped |

Each line is written and flushed to disk (fsync) before the code continues. If a line can't be written, the run stops: the action that tried to log throws `LogWriteError`, every later `bot.*` call is refused before it acts, and a failure inside a timer ends the process with exit code 3.

## Event types

| Type | When | `data` |
|---|---|---|
| `run.start` | The agent's process starts logging into the run (each agent writes its own) | `script`, `args`, `pid`, `joined` (true if it joined an existing run), `condition` |
| `run.end` | The agent's process stops logging | `reason`: `finished`, `stopped` (timeout, Ctrl+C, kill) or `crashed`; `seconds`; `how` and `error` when known |
| `action` | Every `bot.*` call, written when it returns or throws | `name`, `args`, `success`, `message`, `result` (the rest of the result object), `error` (`name`, `message`) if it threw, `ms`, `tickStart` |
| `snapshot` | Every 10 s, plus one at the start and one at the end | `x`, `z`, `level`, `area`, `hp`, `maxHp`, `slotsUsed`, `inventory` (name → count), `xp` (skill → XP, skills above 0 only), `nearbyPlayers` (`name`, `x`, `z`, `distance` in tiles), `stateAgeMs` |
| `location` | The bot enters or leaves a named area (checked every second); the first one says where it starts | `from`, `to` (area names, `null` = no named area), `x`, `z`, `level` |
| `activity.start` | A routine starts | `routine`, `area`, `settings` |
| `activity.end` | A routine stops | `routine`, `area`, `seconds`, `items` (name → change, + gained / − lost), `xp` (skill → XP gained), `reason` (e.g. `backpack_full`, `failure_streak`, `error`), plus whatever the routine adds |
| `problem` | 5 failed actions in a row (`failure_streak`), connection changes (`connection`), no game state (`no_state`) | `kind`, `message`, and `resolved: true` when it is over; `count`, `lastAction` for streaks; `state`, `attempt` for connections |
| `note` | A manual note, e.g. "Jacob restarted the server" (an intervention, a possible confound) | `text` |

Reserved, added when the features exist: `chat`, `trade`, `deal` (promised vs delivered), `model.call` (trigger, model, tokens, cost, duration, files), `memory.updated`, `reflection`, `rating`, `questionnaire`.

What isn't logged: `sdk.*` calls (state queries and low-level sends) and `bot.*` calls made inside other `bot.*` calls (only the outer call is one action). The query helpers `bot.getEquipment` and `bot.findEquippedItem` aren't actions.

## Named areas

`artscape/areas.json`: `"name": { "label", "x": [min, max], "z": [min, max], "level" }`, inclusive tile ranges. The first matching area wins. Events use the name, `timeline.txt` uses the label.

## Code

| File | What it does |
|---|---|
| `log.ts` | Run folders, `run.json`, the per-agent writer (`AgentLog`), JSON-safe values |
| `instrument.ts` | Wraps `bot` (actions), snapshot and location timers, problems |
| `run-logged.ts` | `runLogged(script)`: rs-sdk's `runScript` plus logging; `--run=<id>` joins a run, `--condition=` sets the condition; gives the script `activity(...)` |
| `areas.ts` | Reads `areas.json`, finds the area of a tile |
| `merge.ts` | Builds the timeline and checks the data (valid lines, seq without gaps, run ids) |
| `watch.ts` | Logs a bot without acting (snapshots, location, problems) |
| `selftest.ts` | Offline test of all of the above, no game needed |
