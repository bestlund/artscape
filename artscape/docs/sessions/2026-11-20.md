### 1. Claude Code: content auto-reload off, `::rebuild` kept (16:20–)

Context: at the end of 19 Nov (section 12 there), the engine had reloaded its content three times with no file changed. Claude Code asked whether Jacob had typed `::rebuild` or `::reload`.

1. **Jacob: he did not type `::rebuild` or `::reload`.** He didn't know what auto-reload does, so Claude Code explained: the engine watches the game's content files (maps, NPCs, items, shops, scripts) and repacks and reloads them into the running world when one changes. Only content edits need it; our own code in `artscape/` doesn't. Recommendation: turn it off, because it also fires with no change, and a reload during a run is a confound.
2. **Decision (Jacob): turn auto-reload off, but keep an in-game command to load content updates when convenient.**
3. **Engine log check (16:34): the reloads are periodic.** Since the 16:27 start on 19 Nov the engine reloaded in bursts of 2–3 at 16:30, 17:20, 17:22, 20:18, 21:20, 06:21, 15:29 and 16:29, with no content edited. So something on the machine touches the content files on a schedule (maybe antivirus or the search indexer), and the engine's file watcher reacts. This was also the likely cause in OneDrive, on top of OneDrive itself.
4. **Change (16:30–16:34).** Turning off auto-reload alone (`BUILD_LIVE_RELOAD=false`) would also have disabled `::rebuild`: the engine only started its rebuild worker when auto-reload was on. So, a small engine change:
   - `server/engine/src/cache/DevThread.ts`: the content folders are only watched when live reload is on.
   - `server/engine/src/engine/World.ts`: the rebuild worker now starts on every local world, so a staff **`::rebuild`** repacks and reloads on demand. The startup rebuild still only runs with live reload on.
   - `server/engine/.env` and `.env.example`: `BUILD_LIVE_RELOAD=false`.
   - `server/content/scripts/artscape/scripts/artscape_commands.rs2`: a new page in the `::commands` menu, "Updating the world", with `::rebuild`. (This edit itself caused the reload at 16:34:14, since the old engine was still running.)
5. **Waiting for Jacob:** the engine has to restart to use the new code and setting. The clean way is `::reboot` from Jacob's account (saves everyone; the restart loop starts the engine again). Then Claude Code checks: no watcher reloads, `::rebuild` works, the bots log back in.
