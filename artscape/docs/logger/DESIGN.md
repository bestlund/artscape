## Principles

1. **Never lose or overwrite data.** Each event is written to disk the moment it happens (append-only, flushed per line). A new run never touches an old run's folder. Nothing is ever truncated.
2. **Logging can't be forgotten.** The logger wraps the SDK's `bot`, so every action is recorded automatically. Routine code doesn't have to call the logger itself.
3. **One format.** Every event is one JSON line with the same envelope.
4. **Two clocks.** Real time (`t`, ISO UTC with ms) and game tick (`tick`). `::speed` changes real time per tick, so in-game days are measured in ticks.
5. **One file per agent** (no two processes writing the same file). The combined log is generated by merging the agent files in order. This is Jacob's "separate logs → one log".
6. **Setup recorded at start** in `run.json`: run id, condition, model, memory on/off, rs-sdk version (`b565f2d92`), XP rate (25), tick rate, Grand Exchange on/off, agents and their configs, and a copy of the config files.
7. **Test runs kept apart.** Condition `dev` for anything that isn't an experiment run.
8. **Big content as separate files** (prompts, responses, generated code, memory file versions) in `files/`, referenced from the event, so the timeline stays readable.
9. **Versioned and documented.** `run.json` has a `schema` version; `SCHEMA.md` describes every event type. That becomes the data section of the paper.

## Folder per run

```
runs/<run-id>/                e.g. runs/2026-10-22_1510_dev/
  run.json                    setup of this run
  agents/<agent>.jsonl        everything that agent did, one event per line
  files/                      long texts (prompts, answers, memory versions)
  timeline.jsonl              all agents combined, ordered by time   (generated)
  timeline.txt                the same, human-readable               (generated)
```

Run id: `YYYY-MM-DD_HHMM_<condition>` (plus a suffix if needed), e.g. `2026-10-22_1510_dev`, `2026-11-20_1400_memory-on`.

## Event envelope

```json
{"seq":12,"t":"2026-10-22T15:10:04.512Z","tick":10233,"run":"2026-10-22_1510_dev","agent":"testbot1",
 "type":"activity.end","data":{"routine":"woodcutting","area":"lumbridge_trees","seconds":71,
 "gained":{"Logs":10},"xp":{"Woodcutting":6250},"reason":"backpack_full"}}
```

- `seq`: counter per agent file, starting at 1 (catches gaps, and orders events with equal timestamps)
- `t`: wall-clock time; `tick`: game tick from the bot's state
- `run`, `agent`, `type`, `data`

Readable line in `timeline.txt`:
```
15:10:04  testbot1  finished woodcutting at Lumbridge trees: +10 logs, +6,250 XP (71 s, backpack full)
```

## Event types

| Type | When | Jacob's log |
|---|---|---|
| `run.start` / `run.end` | Start and end of the run (end includes the reason: finished, stopped, crashed) | Setup |
| `activity.start` / `activity.end` | A routine starts or stops: what, where, settings, result, duration | **Activity log** |
| `location` | The agent enters a named area (from `areas.json`) | **Location log** |
| `action` | Every `bot.*` call: name, arguments, success, message, duration | Detail |
| `snapshot` | Every 10 s: position, area, HP, inventory, nearby players | State over time |
| `problem` | Failure streaks, disconnects, exceptions | Errors |
| `note` | Manual notes, e.g. "Jacob restarted the server" | **Interventions** (confounds) |

Reserved, built when the features exist: `chat`, `trade`, `deal` (promised vs delivered; the key data for the hypothesis), `model.call` (trigger, model, tokens, cost, duration, files), `memory.updated`, `reflection`.

## Named areas

`areas.json`: name → rectangle (+ level), e.g. `lumbridge_trees`. The location log and snapshots use names instead of coordinates. It starts with the few areas we use, and the custom world gets its own areas later.

## Build order

1. Logger core: run folder, `run.json`, per-agent writer (append + flush, stop on failure), envelope, `note`
2. Automatic `action` logging (wrap `bot`) + `snapshot` timer + `location` from `areas.json`
3. `activity.start/end` around routines (with `chop-loop.ts` as routine #1)
4. Merge tool: `timeline.jsonl` + readable `timeline.txt`
5. `SCHEMA.md`
6. Test on a `dev` run with `testbot1`, check the files by hand
